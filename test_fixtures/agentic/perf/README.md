# Performance-spec inputs

Generated by `python -m edat.cases.perf_inputs --out test_fixtures/agentic/perf` (seed 41, deterministic; spec: `02-agentic-spec.md` section 11). All text is synthetic: names from `edat/cases/generators/pools.py`, invented values, `example.com` / `example.org` addresses. Token figures are estimates at 4 characters per token (message contents, tool-call JSON and tool-schema JSON); the performance spec's pack builder applies the chat template, tokenises and trims exactly.

| File | What |
|---|---|
| `edat-agent-corpus-v1.jsonl` | One assistant-lane request per level (512, 1,024, 2,048, 5,120, 10,240, 32,768, 65,536). Estimate is at most the level and within 5% below it. |
| `edat-agent-trajectory-v1.json` | The fixed 6-step task with a 4,096-token estimated shared prefix and canned assistant outputs and tool results. |
| `edat-sim-day-v1.json` | The 10-hour simulated day: 47 jobs, `mode: forced`, compressed option `idle_scale: 0.2`. |
| `edat-duty-cycle-v1.json` | The 20-burst heavy-use hour (one 6-step trajectory every 3 minutes, nonce variant i; bursts 17-20 reuse variants 0-3 with a fresh cache). |

## Corpus record

`messages` are OpenAI-style (`assistant.tool_calls`, `tool.tool_call_id`). History is groups of four messages (user request, assistant tool call, tool result, assistant one-line summary) drawn without replacement from a generated pool of 2,000 distinct records (emails, calendar listings, reminders, notes, web snippets, messages). No paragraph (line of 40+ characters) repeats inside a level; the only repeated lines are the email tool's fixed `<<<untrusted email body ...>>>` wrapper tags.

`trim.message_range` is `[1, -2]`, inclusive on both ends: from the first history message to the last one before the final user turn. `trim.records` counts the whole four-message records; the pack builder cuts whole records first, then tokens. `estimate.history_records` lists the pool ids used. The head, menu and final turn are fixed per level.

Compromises forced by the real assistant-lane sizes (the spec's token table assumed a ~600-token prompt; the real prompt is about 4,500 estimated tokens for a 12-tool menu, and the 12 real schemas alone are about 4,400):

- 512, 1,024, 2,048 and 5,120: the head is the real prompt cut at a sentence or word boundary (about 750, 530, 750 and 1,000 characters) with the real date line kept; the 512 to 2,048 menus are small real schemas (2, 4, 6) and the history tools are in the menu.
- 5,120 carries the 12-schema menu, so it has only about 1,700 characters of history (2 records).
- 10,240 and above use the full prompt for the 12-tool menu (`system_prompt(offered=...)`, about 17,900 characters).

## Trajectory

`prefix` = system head, six schemas (the six tools the task uses), one earlier exchange (a parallel catch-up of several reads) marked trimmable (`trim.message_range [1, -1]`). The exchange is sized so the prefix estimate is 4,096. Step k's `messages` are what is appended before generation: the user request at step 1, then the previous step's canned assistant message and tool results. `canned_assistant` is the teacher-forced output; `canned_tool_results` follow it. `estimated_input_tokens` runs from about 4.1k (step 1) to about 5.4k (step 6).

Deviation from the spec: the spec says full prompt plus 12 schemas inside 4,096 tokens, which is arithmetically impossible with the real assistant lane (see above). The prefix uses the six needed schemas and the head cut at 3,500 characters.

## Simulated day

`events[].t` is `HH:MM:SS` on the board clock; kinds `brief`, `task`, `mail_digest`, `message_digest`, `review`. Task refs are public development-split case ids (assistant lane, `core` preferred, drawn with the recorded seed); `ref: null` plus an entry in `missing` marks a family with too few cases when the file was generated. Regenerate after the family case files land. `world_events_before` holds the synthetic emails (2-5 before each mail digest) or messages (2-4 before each message digest) that arrive since the previous digest of that kind. `jobs` describes the non-task job shapes.
